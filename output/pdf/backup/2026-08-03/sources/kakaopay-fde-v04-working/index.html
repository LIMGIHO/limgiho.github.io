통합

실행 구조
공식 API가 없는 글로벌 물류 운영 시스템(UFS+)과 연동하기 위해 Okta·Microsoft Entra 인증 흐름과 업무 요청을 HTTP 수준에서 구현했습니다. 스케줄 실행과 BullMQ 작업 소비는 Worker로 분리하고, Worker가 내부 HTTP API를 호출해 인증·업무 처리·데이터 저장은 API 서버가 맡도록 경계를 나눴습니다.
자동화 이전
기존 C# 기반 삼성 물류 시스템(NERP) 연동 프로그램의 인증·요청 흐름을 HTTP 단위로 분석해 통합 플랫폼의 API·Worker 구조로 이전했습니다. 문서 검증과 데이터 입력, 개별 운송장 마감, 인보이스 생성, 통합 운송장 마감을 하나의 작업 흐름으로 자동화했습니다.
운영 구조
Express 백엔드를 NestJS 도메인 모듈로 재구성하고 Redis·BullMQ로 무거운 작업을 비동기 처리했습니다. PM2 수동 배포를 GitLab CI/CD·Docker Swarm 기반으로 전환해 테스트가 실패한 변경을 배포 전에 차단하고, 커밋 단위 이미지로 배포 이력과 롤백 기준을 만들었습니다. 빌드 단계를 측정해 일반 변경은 8분에서 6분으로 줄였지만, 추가 단축안은 GitLab과 Runner가 같은 호스트에 있어 권한 위험이 커진다고 판단해 적용하지 않고 Runner 분리를 후속안으로 계획하고 있습니다.
결과
개별 운송장 마감, 인보이스 생성, 통합 운송장 마감으로 이어지는 업무를 자동화했습니다. 실패 건은 재시도하고 진행 상태를 추적할 수 있게 해 월 1,200시간 상당의 반복 작업을 줄였습니다. 관세청 조회는 건당 약 10분에서 5초 이내로 단축했습니다.
