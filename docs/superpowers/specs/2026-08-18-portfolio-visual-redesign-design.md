# 포트폴리오 시각 리디자인 설계

## 목적

현재 포트폴리오는 내용의 밀도는 충분하지만 첫 화면에 지원자가 없다. 이름, 직함, 연락처, 진입점 없이 `01 · CAREER JOURNEY`로 시작하고, 내비게이션과 이미지가 없어 짧은 시간에 훑는 채용 담당자가 붙잡을 지점이 없다.

이 작업은 내용을 바꾸지 않는다. 이미 확보된 사실과 지표를 **읽히는 순서와 시각적 위계로 재배치**하고, 두 개의 테마로 화면 톤을 선택할 수 있게 만든다.

## 배경: 참고 사이트에서 무엇을 가져오고 무엇을 버리는가

`https://dlwjdtn535.github.io/` 를 실측 검토했다. 1:1 복제는 하지 않는다. 이유는 두 가지다.

첫째, 해당 저장소는 공개이지만 라이선스가 없다(`license: null`). 라이선스 없는 공개 저장소는 기본이 모든 권리 보유이므로, 디자인과 코드를 그대로 옮겨 본인 이름으로 게시하는 것은 허가받지 않은 사용이다.

둘째, 구조가 맞지 않는다. 참고 사이트는 다수의 단기 프리랜서 프로젝트를 나열하는 형태다. 이 포트폴리오의 중심은 하나의 깊은 사례(15종 운영 시스템을 단일 플랫폼으로 전환)이고, 그 근거인 아키텍처 다이어그램은 참고 사이트에 없는 자산이다.

가져오는 것은 다음과 같다. 첫 화면의 정보 밀도, 핵심 지표의 시각적 강조, 스티키 내비게이션, 시각 자산이 붙은 타임라인, 스크롤 등장 모션, 명시적 연락 경로.

버리는 것은 다음과 같다. 숙련도 백분율 막대(`Java 95%` 형태), 파스텔 그라데이션 톤, 실무가 아닌 데모 카드 나열.

## 히어로에 대한 판단

`2026-08-15-portfolio-first-screen-revision-design.md`는 "경력기술서와 중복되는 표지형 Hero"를 제거했다. 그 판단의 근거는 유효하다. 이번에 되살리는 히어로는 표지가 아니어야 한다.

되살리는 히어로가 지켜야 할 조건은 다음과 같다.

- 경력기술서 문장을 반복하지 않는다. `portfolio_profiles.yml`의 `headline`과 `summary`만 쓴다.
- 장식용 일러스트나 인물 사진을 넣지 않는다.
- 화면 한 칸을 온전히 차지하지 않는다. 첫 화면 안에서 히어로 아래로 `01 CAREER JOURNEY`의 시작이 보여야 한다.
- 지표 4개는 링크로 동작한다. 각 지표는 그 근거가 있는 섹션으로 이동한다.

즉 히어로는 표지가 아니라 **진입점 겸 요약 지표 바**로 정의한다.

## 화면 구조

레이아웃은 하나이고 테마 두 개가 토큰만 교체한다.

### 스티키 내비게이션 (신규)

상단 고정. 항목은 `임기호`, `경력`, `플랫폼`, `자동화`, `개인 프로젝트`, `이력서 PDF`, 테마 토글이다. 스크롤 진행 표시를 포함한다. 현재 보고 있는 섹션을 표시한다.

### 00 히어로 (복원)

`portfolio.person`의 이름, `profile.eyebrow`, `profile.headline`, `profile.summary`를 렌더한다. `profile.metrics`가 가리키는 지표 4개를 표시하고, 각 지표는 근거 섹션으로 이동하는 링크로 만든다. 진입 버튼은 `대표 프로젝트 보기`와 `이력서 PDF` 두 개다. GitHub와 이메일을 함께 노출한다.

데이터는 이미 모두 `_data`에 존재한다. 이 섹션은 렌더링만 복원하는 작업이다.

### 01 Career Journey (유지, 대비 강화)

4개 항목 타임라인을 유지한다. 회사명과 역할의 시각적 대비를 높이고 현재 재직 항목을 강조한다. `is-current` 처리는 `assets/js/portfolio.js`에 이미 있다.

### 02 통합 업무 플랫폼 (개선, 이 문서의 중심)

순서는 지표 요약, 전환 전후 다이어그램, 인터랙티브 아키텍처 다이어그램, 구현 상세다.

전환 전후 다이어그램을 새로 만든다. `15 → 1`은 현재 표 안의 작은 글자로만 존재한다. 이것을 분산된 15개 단위와 통합된 6개 실행 단위(Web, API, Queue, Worker, Batch, Data)의 대조로 보이게 한다. 이 다이어그램은 인라인 SVG로 만들고 `_data/portfolio.yml`의 실제 노드 정의에서 유도한다. 별도의 사실을 새로 만들지 않는다.

기존 인터랙티브 아키텍처 다이어그램과 구현 상세는 구조를 바꾸지 않는다. 테마 토큰만 적용한다.

### 03 자동화 (개선)

문제와 역할, 검증·처리·예외 3단계, 결과(월 1,200시간) 구조를 유지한다. 익명화 UI 목업을 추가해 자동화 대상 화면의 형태를 보여준다.

목업은 두 개를 만든다. 하나는 자동화 이전의 수기 입력 화면, 하나는 검증 규칙이 적용된 이후 화면이다. 두 화면의 대조가 이 섹션의 논점이다.

익명화 목업의 제약은 다음과 같다. 실제 스크린샷을 쓰지 않는다. 고객사명, 내부 시스템명, 사설 주소, 실데이터를 넣지 않는다. 화면의 레이아웃 구조만 재현하고 값은 가상으로 채운다. 목업은 이미지 파일이 아니라 인라인 SVG 또는 HTML로 만들어 테마에 따라 색이 따라오게 한다.

### 04 경력과 기술 (유지)

KWE Korea와 ILJIN Global 상세, Technology in context 4분류를 유지한다. 숙련도 백분율 막대는 넣지 않는다.

### 05 개인 프로젝트 (개선)

댓글 필터, 액션독, HealthDog. Google Play 스토어에 이미 공개된 실제 스크린샷을 사용한다. 이 섹션이 실제 제품 이미지가 들어가는 유일한 곳이다. 앱당 1장에서 2장으로 제한한다. 카드 크기를 넘는 갤러리는 만들지 않는다.

이미지는 저장소에 내려받아 넣고 원격 URL을 참조하지 않는다. 컴파일된 CSS에 `url(http` 가 들어가면 검증이 실패한다. 이미지는 폭 기준으로 축소해 넣고 각 파일은 200KB를 넘지 않게 한다. 현재 저장소에 있는 `images/AttackonTitan.png`는 2.8MB이며 테마에서 물려받은 잔여 파일이므로 이번 작업과 무관하다.

### 푸터 (신규)

이메일, GitHub, 이력서 PDF. 영업 문구인 `문의하기`와 `상담 신청`은 쓰지 않는다.

## 테마

두 테마를 `body` 클래스로 분기한다. 현재 구조인 `theme-{{ profile.theme }}`를 그대로 쓴다.

`theme-blueprint`는 어두운 배경의 설계도 톤이다. 배경은 짙은 남색, 강조는 시안, 지표는 고정폭 글꼴, 옅은 격자 배경을 쓴다. 아키텍처 다이어그램의 선과 노드 대비가 가장 잘 살아난다.

`theme-editorial`은 밝은 배경의 편집 지면 톤이다. 따뜻한 오프화이트 배경, 넓은 여백, 굵은 표제, 얇은 구분선을 쓴다. 긴 케이스 스터디 읽기와 인쇄 출력에 유리하다.

기존 `theme-ice-blue`와 `theme-graphite-yellow`는 제거한다. 두 테마를 남긴 채 새 테마를 더하면 기본 페이지에 톤이 셋이 되어 토글의 의미가 사라진다. 프로필의 `theme` 값은 기본 톤 하나를 가리키고, 값은 `blueprint`와 `editorial` 둘뿐이다.

`default` 프로필은 `blueprint`, `kakao` 프로필은 `editorial`을 기본값으로 쓴다. `scripts/verify-portfolio.py`의 `RENDERED_PROFILES`가 기대하는 테마 클래스도 함께 바꾼다.

테마 토글은 사용자의 선택을 `localStorage`에 저장한다. 저장된 값이 없으면 프로필에 지정된 테마를 쓴다. 토글은 톤만 바꾸며 문구, 지표, 섹션 구성은 프로필이 계속 결정한다.

## 모션

참고 사이트를 스크롤하며 캡처했을 때 내용이 아직 나타나지 않은 빈 화면 구간이 반복해서 관찰됐다. 등장 애니메이션이 콘텐츠 표시의 전제조건으로 걸려 있기 때문이다.

이 문제를 피하기 위해 기본 상태를 "보임"으로 둔다. 요소는 CSS만으로 이미 보이는 상태이고, JavaScript가 로드된 뒤에만 등장 효과용 클래스를 붙인다. `prefers-reduced-motion: reduce`와 인쇄 상황에서는 효과를 적용하지 않는다. JavaScript가 실패해도 모든 내용이 보인다.

`IntersectionObserver`를 쓰고, 한 번 나타난 요소는 다시 숨기지 않는다.

## 코드 구조

`assets/css/portfolio.scss`가 951줄이다. 여기에 두 테마와 새 섹션을 그대로 얹으면 더 커진다. 이번 작업 범위 안에서 파티셜로 분리한다.

분리 기준은 다음과 같다. 토큰과 테마 정의, 레이아웃과 타이포그래피, 섹션별 컴포넌트. 각 파티셜은 하나의 책임을 갖고 `portfolio.scss`가 이들을 불러온다. 이 분리는 이번 작업이 건드리는 파일에 한정한다. 관련 없는 리팩터링은 하지 않는다.

`_includes/portfolio/`에 `hero.html`, `nav.html`, `footer.html`, `transition.html`을 추가한다. 기존 include의 책임 경계는 바꾸지 않는다.

`assets/js/portfolio.js`에 내비게이션, 테마 토글, 등장 모션을 추가한다. 파일이 커지면 기능 단위로 분리한다.

## 선행 작업: 깨진 검증 복구

리디자인을 시작하기 전에 현재 저장소를 통과 상태로 되돌린다.

`python3 scripts/verify-portfolio.py --source-only`가 현재 실패한다. 커밋 `edab395`에서 `legacy-api` 노드와 `migration` 흐름을 제거했으나 `scripts/verify-portfolio.py`의 `REQUIRED_ARCHITECTURE_NODE_IDS`와 `REQUIRED_ARCHITECTURE_FLOWS` 상수를 갱신하지 않았다. 렌더 검증의 노드 개수 기대값 10도 함께 맞춰야 한다.

`_data/portfolio.yml`과 `assets/js/portfolio.js`에 커밋되지 않은 변경이 있다. 노드 좌표 조정과 `icon` 필드 추가다. 이 변경을 먼저 정리하고 커밋한 뒤 리디자인을 시작한다.

깨진 검증 위에 새 작업을 얹지 않는다.

## 검증 계약 변경

`scripts/verify-portfolio.py`와 `tests/test_verify_portfolio.py`의 금지 목록을 조정한다.

해제하는 것은 `class="portfolio-hero"` 하나다. 금지에서 빼는 데 그치지 않고 반대로 히어로가 **존재해야 한다**는 확인으로 바꾼다. 이름, `headline`, 지표 4개, 이력서 링크, GitHub 링크가 렌더 결과에 있어야 한다.

유지하는 것은 다음과 같다. `skill-bar`, `progress-bar`, `aria-valuenow`는 계속 금지한다. 숙련도 백분율 표시는 시니어 직군 심사에서 근거 없는 자기평가로 읽힌다. `문의하기`와 `상담 신청`도 계속 금지한다.

추가하는 확인은 다음과 같다. 스티키 내비게이션과 5개 섹션 앵커가 존재해야 한다. 두 새 테마 클래스가 컴파일된 CSS에 있어야 한다. 익명화 위반 패턴 검사(`FORBIDDEN_PATTERNS`)는 새로 추가되는 목업과 이미지 대체 텍스트에도 그대로 적용된다.

기존 CSS 계약(`--accent`, `--ink`, `prefers-reduced-motion`, `@media print`, `@page`, `transition: all` 금지, `url(http` 금지)은 모두 유지한다.

## 작업 순서

범위가 넓으므로 각 단계가 끝날 때마다 빌드와 검증이 통과하는 상태를 유지한다. 앞 단계가 초록이 아니면 다음 단계로 넘어가지 않는다.

1. 깨진 검증 복구와 미커밋 변경 정리. 리디자인 코드는 건드리지 않는다.
2. 테마 토큰 체계와 SCSS 파티셜 분리. 화면 결과는 기존과 동일하게 유지한 채 구조만 바꾼다.
3. 스티키 내비게이션과 푸터 추가. 검증 계약도 함께 갱신한다.
4. 히어로 복원. 금지 목록에서 해제하고 필수 확인으로 전환한다.
5. 전환 전후 다이어그램 추가.
6. 자동화 섹션 익명화 목업 2종 추가.
7. 개인 프로젝트 실제 스크린샷 추가.
8. 등장 모션 적용. 마지막에 붙인다. 모션 없이 완성된 화면 위에 얹어야 모션이 내용을 가리지 않는다는 것을 확인할 수 있다.

2단계에서 화면이 달라 보이면 토큰 추출이 잘못된 것이다. 그 시점에 되돌린다.

## 검증

- `bundle exec jekyll build`가 성공한다.
- `python3 scripts/verify-portfolio.py --site-dir _site`가 통과한다.
- `python3 -m pytest tests/` 또는 기존 테스트 실행 방식이 통과한다.
- 기본 프로필과 카카오 프로필 두 페이지가 모두 렌더된다.
- 데스크톱과 모바일 폭에서 히어로, 내비게이션, 전환 다이어그램, 아키텍처 다이어그램의 정렬과 겹침을 확인한다.
- 두 테마를 토글하며 대비를 확인한다. 본문 텍스트는 WCAG AA를 만족한다.
- JavaScript를 끈 상태에서 모든 섹션의 내용이 보인다.
- 인쇄 미리보기에서 내비게이션이 제외되고 본문이 A4에 정상 배치된다.

## 범위 밖

- PDF 생성. 화면과 문구가 확정된 뒤 별도로 요청받아 진행한다.
- `_data/portfolio.yml`의 사실 관계 변경. 이번 작업은 표현만 바꾼다.
- 새 지원처 프로필 추가.
- 실제 업무 화면 스크린샷 사용. 익명화 목업으로 대체한다.
