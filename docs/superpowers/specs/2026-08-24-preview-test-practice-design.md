# Node.js Preview Test 사전 연습 설계

**목표:** 실제 채용 과제를 공유하거나 재현하지 않고, 익숙한 TypeScript 환경에서 요구사항 분석부터 구현·테스트·문서화까지 두 번 완주해 생성형 AI 의존 없이 코딩하는 감각을 회복한다.

## 전제와 보안 경계

- 실제 Preview Test는 2026-08-29 14:00에 시작하고 48시간 뒤인 2026-08-31 14:00에 마감한다.
- 첫 번째 과제는 월요일 1시간 동안 시작하고, 화요일 업무 중 구조를 고민한 뒤 19:00~22:00에 구현을 마무리한다.
- 수요일에는 첫 번째 과제를 리뷰하고, 두 번째 과제는 목요일과 금요일 19:00~22:00에 진행한다.
- 실제 문제, 요구사항, 제공 코드, 테스트, 데이터 구조, 고유 오류 로그는 외부 LLM에 입력하지 않는다.
- 실제 과제 중 일반적인 문법·함수·이론을 확인할 때는 공식 문서와 일반 검색을 우선한다. LLM을 참고한다면 실제 과제의 맥락이 전혀 없는 독립적인 질문으로 제한한다.
- 모의 과제는 토스, 금융, 모바일 디바이스, 테스트 자동화와 무관한 일반 도메인을 사용한다.

## 연습 방식

두 개의 모의 과제를 다음 일정으로 진행한다.

- 모의 과제 1: 월요일 1시간 + 화요일 3시간, 화요일 업무 중에는 구현 없이 구조만 검토
- 모의 과제 1 리뷰: 수요일
- 모의 과제 2: 목요일 3시간 + 금요일 3시간

하루 작업 시간은 제출 제한이 아니라 연습을 위한 체크포인트다. 첫 번째 과제는 짧은 기준점 측정에, 두 번째 과제는 리뷰에서 발견된 약점을 반영해 끝까지 완주하는 데 목적을 둔다.

## 모의 과제 1

익숙한 `NestJS + Vitest`를 기준으로 일반적인 예약 중계 API를 구현한다. 외부 예약 공급자와의 통신은 HTTP로 한정하며, 파일 데이터베이스에 처리 상태를 저장한다.

연습 대상은 다음과 같다.

- 제공된 의존성을 바꾸지 않고 프로젝트 구조 결정
- 요청 검증과 명시적인 상태 전이
- 외부 HTTP 호출의 성공·실패·타임아웃 처리
- 중복 요청에 대한 일관된 결과
- 파일 데이터베이스 영속성
- 단위 테스트와 HTTP 경계의 통합 테스트
- 실행 방법, 가정, 설계 판단을 설명하는 README

스타터 디렉터리에는 사용자가 요청한 대로 `package.json`만 제공한다. 소스 코드, 설정 파일, 테스트, README, 정답 구현은 제공하지 않는다. 과제 요구사항은 대화에서 별도로 전달한다.

## 모의 과제 2 선택 규칙

첫 번째 과제 리뷰에서 가장 큰 병목 하나를 선정해 두 번째 과제를 조정한다.

- 핵심 기능까지 완주했다면 다른 통신 형태가 지정된 새 스타터로 적응력을 연습한다.
- 프로젝트 설정이나 기본 구현에서 막혔다면 같은 스택을 유지하고 다른 일반 도메인으로 다시 완주한다.
- 테스트가 병목이었다면 기능 범위를 줄이고 실패 경로와 통합 테스트 비중을 높인다.
- 설계가 병목이었다면 상태 전이와 모듈 경계가 명확한 요구사항으로 다시 연습한다.

이 선택 규칙은 실제 과제 기술을 예측하기 위한 것이 아니라 첫 연습에서 관찰된 약점을 한 번 더 훈련하기 위한 것이다.

## 파일 위치와 저장소 영향

- 연습 파일은 `tmp/preview-test-practice/mock-1/`과 `tmp/preview-test-practice/mock-2/`에 둔다.
- 포트폴리오의 애플리케이션 코드와 데이터는 변경하지 않는다.
- 연습 산출물은 커밋하지 않는다.
- 설계 문서만 현재 저장소에 기록하며, 기존의 수정·미추적 파일은 건드리지 않는다.

## 완료 기준

- 각 모의 과제가 합의한 연습 시간 안에 실행 가능한 상태가 된다.
- 정상 흐름과 핵심 실패 흐름이 테스트로 검증된다.
- 애플리케이션 재시작 뒤에도 필요한 상태가 유지된다.
- README만 보고 설치, 실행, 테스트할 수 있다.
- 구현하지 못한 항목이 있다면 숨기지 않고 이유와 다음 선택을 기록한다.
