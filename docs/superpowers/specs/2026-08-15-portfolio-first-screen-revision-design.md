# 포트폴리오 첫 화면 수정 설계

## 목적

포트폴리오를 완성본처럼 포장하기보다 로컬 화면에서 내용을 계속 다듬을 수 있는 상태로 되돌린다. 경력기술서와 중복되는 표지형 Hero는 제거하고, 첫 화면부터 실제 경력과 프로젝트 근거를 보여준다.

## 화면 구성

- 큰 헤드라인, 소개 문장, 핵심 지표, PDF·GitHub 버튼으로 구성된 Hero 전체를 제거한다.
- 첫 번째 섹션은 기존 `Career Journey` 타임라인을 유지한다.
- 섹션 제목은 `주요 경력`으로 바꾼다.
- 설명은 `제조·물류 시스템을 개발하고 운영해 온 경험을 시간순으로 정리했습니다.`로 바꾼다.
- 타임라인의 회사명과 기간은 유지한다.
- `책임`, `리드`, `전환`처럼 성과를 과장해 보일 수 있는 제목 대신 실제 수행 업무를 직접 적는다.
- 공식 직급과 역할은 뒤의 경력 섹션에서 확인할 수 있으므로 Career Journey 메타에는 회사명만 표시한다.

## 타임라인 문체

- `제조 현장의 데이터를 시스템으로 연결` → `MES·ERP 업무 시스템 개발`
- `국내외 공장 MES 고도화를 리드` → `국내외 공장 MES 고도화`
- `물류 업무 자동화와 데이터 전환`은 사실 중심이므로 유지한다.
- `레거시를 통합 플랫폼으로 전환` → `통합 업무 플랫폼 개발 및 운영`
- 설명은 수행한 대상과 작업을 담되 자기평가나 홍보 문구를 추가하지 않는다.

## PDF 처리

- 조기에 생성한 기본·카카오 포트폴리오 PDF 두 파일은 저장소에서 제거한다.
- PDF 생성 스크립트는 향후 명시적인 PDF 제작 요청에 사용할 수 있도록 남긴다.
- 현재 테스트와 문서는 PDF 파일이 항상 존재한다고 가정하지 않도록 바꾼다.
- 이번 수정 과정에서는 PDF를 생성하거나 렌더 검수하지 않는다.

## 검증

- Jekyll 빌드가 성공해야 한다.
- 기본·카카오 프로필 모두 Hero 없이 `Career Journey`가 첫 콘텐츠로 렌더링되어야 한다.
- 새 제목과 설명이 표시되고 기존 과장 문구가 렌더 결과에 없어야 한다.
- 데스크톱과 모바일 로컬 화면에서 첫 섹션의 여백과 타임라인 정렬을 확인한다.
- 포트폴리오 PDF 파일이 추적 대상에서 제거되어야 한다.
