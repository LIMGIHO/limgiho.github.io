# 카카오페이 FDE 이력서 v04 UFS+ 문안 수정 설계

작성일: 2026-08-02

## 목적

v04의 UFS+ 프로젝트 설명을 실제 업무 범위와 시스템 구조에 맞게 고친다. `본사 시스템`, `무인 연동`, 로그인·조회 중심의 설명은 제거하고, 세계 80개국에서 사용하는 글로벌 물류 시스템 UFS+의 업무 자동화와 월 1,200시간 성과를 중심으로 다시 작성한다.

수정 대상은 아래 v04 전용 파일이다.

- `resumes/kakaopay-fde-v04/index.html`
- `scripts/verify-kakaopay-fde-v04-resume.py`
- `output/pdf/versions/lim-giho-kakaopay-fde-resume-v04.pdf`

기존 v03, Claude 버전, `resumes/kakaopay-fde/`의 미커밋 변경은 건드리지 않는다.

## 확인된 사실

- UFS+는 KWE에서 `본사 시스템`보다 `글로벌 시스템`으로 부른다.
- UFS+는 세계 80개국 사이트에서 사용하는 글로벌 물류 시스템이다.
- 과거 삼성 NERP 입력 RPA를 현재 UFS+ 기반 자동화 구조로 마이그레이션했다.
- 두 표현은 같은 자동화 업무를 가리키며, 이력서에서는 현재 구조인 UFS+ 자동화를 기준으로 쓴다.
- 자동화 범위는 하우스 마감, 인보이스 생성, 마스터 마감으로 이어진다.
- 이 자동화로 월 1,200시간 상당의 반복 작업을 줄였다.
- 모노레포에는 프론트엔드, API, Worker, 공용 라이브러리가 포함된다.
- Worker는 스케줄 실행과 BullMQ 작업 소비를 담당하고 내부 HTTP API를 호출한다.
- UFS+ 인증, 업무 처리, 데이터 저장은 API 서버에 남긴다.
- E2E 테스트의 핵심은 내부 시스템명이 아니라 레거시 실데이터를 신규 화면에 직접 입력해 실제 사용자 경로를 검증한 데 있다.

## 수정 방향

### 1페이지

`본사 UFS+`와 `본사 시스템`을 모두 `글로벌 물류 시스템 UFS+` 또는 `글로벌 시스템`으로 바꾼다.

KWE 연도별 업무 제목은 아래처럼 수정한다.

> 웹 업무 플랫폼 구축과 글로벌 시스템 자동화

주요 결과에는 아래 내용을 넣는다.

> UFS+ 업무 자동화 · 하우스 마감·인보이스 생성·마스터 마감 자동화, 월 1,200시간 상당 반복 작업 절감

### 주요 프로젝트 제목

기존 `업무 플랫폼 통합과 본사 시스템 무인 연동`을 아래 제목으로 바꾼다.

> 업무 플랫폼 통합과 글로벌 물류 시스템 자동화

`무인 연동`은 사용하지 않는다. 자동화의 대상이 시스템 연결 자체가 아니라 실제 물류 업무 흐름이기 때문이다.

### 배경

`3개 DBMS를 사용했다`거나 장애 원인을 찾으려고 부서를 옮겨 다녔다는 식의 문장은 사용하지 않는다. 시스템과 데이터가 분산돼 같은 정보를 다시 입력하고 대조했던 업무 문제를 직접 설명한다.

기준 문안:

> 15종 이상의 개별 프로그램과 서로 다른 데이터베이스에 항공·해운·재무 업무가 분산돼 있었습니다. 업무 단계마다 시스템과 데이터 기준이 달라 같은 정보를 다시 입력하거나 수기로 대조하는 일이 반복됐습니다.

### 플랫폼 구조

기존 화면을 복제한 것이 아니라 업무 단위로 5개 플랫폼을 구성한 사실을 유지한다. 모노레포 설명은 실제 구성요소만 적는다.

기준 문안:

> 기존 화면을 그대로 옮기지 않고 항공·해운 수출입과 재무를 기준으로 5개 업무 플랫폼을 구성했습니다. 프론트엔드·API·Worker·공용 라이브러리는 모노레포로 묶어 함께 관리했습니다.

### Worker 분리

화면과 배치가 같은 조회 경로를 사용한다는 설명은 삭제한다. Worker가 업무 모듈을 직접 실행하지 않고 내부 HTTP API를 호출하는 현재 경계를 설명한다.

기준 문안:

> 스케줄 실행과 BullMQ 작업 소비는 Worker로 분리했습니다. Worker는 업무 코드를 직접 실행하지 않고 내부 HTTP API를 호출하며, UFS+ 인증과 업무 처리, 데이터 저장은 API 서버가 담당하도록 경계를 나눴습니다.

### 자동화와 성과

로그인과 조회 자동화만 구현한 것처럼 보이는 문장은 삭제한다. 과거 NERP 입력 RPA를 현재 UFS+ 처리 흐름으로 마이그레이션한 사실, 업무 범위, 운영 상태 추적과 성과를 함께 쓴다.

기준 문안:

> 기존 삼성 NERP 입력 RPA를 UFS+ 기반 처리 흐름으로 마이그레이션했습니다. 하우스 마감부터 인보이스 생성, 마스터 마감까지 이어지는 작업을 자동화하고 실패 건의 재시도와 진행 상태를 추적할 수 있게 했습니다. 이를 통해 월 1,200시간 상당의 반복 작업을 줄였습니다.

`월 1,200시간`은 사용자가 확인한 실제 절감 성과이므로 삼성 전세기 프로젝트의 `월 약 200시간 규모`와 다르게 `절감`으로 표현한다.

### AI MVP와 E2E 테스트

`AEPOS`라는 내부 시스템명은 이력서에서 삭제한다. AI 에이전트의 사용량보다 실제 사용자 경로를 검증하는 E2E 테스트를 만든 사실을 강조한다.

기준 문안:

> 레거시 실데이터를 신규 화면에 직접 입력하는 Playwright E2E 테스트를 만들었습니다. DB나 API로 데이터를 넣는 방식으로는 발견하기 어려운 입력 폼, 저장, 화면 간 업무 흐름을 실제 사용자 경로로 검증했고, 이 과정에서 데이터 마이그레이션 오류를 확인했습니다.

## 문체와 레이아웃

- 프로젝트의 고정 라벨은 `배경·구조·분리·성과`처럼 실제 내용에 맞게 바꾼다.
- 로그인 과정 자체를 성과처럼 강조하지 않는다.
- `본사`, `무인 연동`, `AEPOS`, `3개 DBMS`, `화면과 배치가 같은 조회 경로`를 사용하지 않는다.
- `월 1,200시간 상당 반복 작업 절감`과 `월 약 200시간 규모`를 서로 혼동하지 않는다.
- 기존 3페이지 A4 구성과 현재 디자인을 유지한다.
- 글자 크기를 줄여 억지로 맞추지 않고 문장 중복을 줄여 페이지를 맞춘다.

## 검증 기준

- v04 HTML과 PDF에 `글로벌 물류 시스템 UFS+`가 포함된다.
- `하우스 마감`, `인보이스 생성`, `마스터 마감`, `월 1,200시간`이 포함된다.
- 모노레포 설명에 `프론트엔드`, `API`, `Worker`, `공용 라이브러리`가 포함된다.
- Worker가 내부 HTTP API를 호출하고 업무 처리와 데이터 저장은 API 서버가 담당한다는 경계가 드러난다.
- `본사`, `무인 연동`, `AEPOS`, `3개 DBMS`, `부서를 옮겨`, `화면과 배치가 같은 조회 경로`가 남아 있지 않다.
- E2E 설명에 `레거시 실데이터`, `신규 화면`, `Playwright E2E 테스트`가 포함된다.
- PDF는 A4 3페이지이며 잘림과 겹침이 없다.
- 기존 v03, Claude PDF와 `resumes/kakaopay-fde/` 파일의 해시는 작업 전후 동일하다.
