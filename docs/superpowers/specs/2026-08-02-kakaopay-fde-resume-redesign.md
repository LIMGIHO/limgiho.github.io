# 카카오페이 FDE 이력서 재설계

작성일: 2026-08-02

## 수정 목적

현재 이력서는 지원 직무와의 연관성을 설명하려다 발표 자료처럼 보이는 문구와 장식을 사용했다. 이를 일반적인 한국형 경력 이력서 형식으로 바꾼다. 지원자 스스로 의미를 해석해 주는 문장보다 회사, 기간, 담당 업무, 기술, 결과를 앞에 둔다.

내용의 중심은 그대로 유지한다. KWE 입사 후 여러 레거시 시스템을 통합하고 개발·운영 기반을 정비한 뒤 AI를 이용한 빠른 MVP 검증으로 범위를 넓혀 온 경력이다. 다만 `여정`, `역할과 맞닿는 경험`, `작동하는 시스템으로 확인`처럼 편집자가 붙인 문구는 사용하지 않는다.

## 형식

- A4 3페이지 단일 컬럼
- 흰 배경, 검정과 짙은 회색 중심
- 노란색은 페이지 상단의 얇은 선과 구분 표시에만 사용
- 카드, 큰 숫자 타일, 영문 eyebrow, 장식용 섹션 번호 제거
- 제목과 본문 크기 차이를 줄여 일반 경력기술서처럼 구성
- 하단 표기는 모든 페이지에서 `limgiho`로 통일

## 문서 구조

### 1페이지: 기본 정보와 KWE 경력 요약

상단에는 다음 정보만 둔다.

- 임기호
- 소프트웨어 엔지니어
- 이메일, 전화번호, GitHub, 상세 경력기술서 링크
- 지원 분야: 카카오페이 FDE

상단 소개 문단은 `경력 요약`으로 바꾼다. 자기평가나 구호를 쓰지 않고 다음 사실을 3~4개 항목으로 정리한다.

- 제조 MES와 물류 업무 시스템을 합쳐 15년 이상 개발·운영
- KWE의 15종 이상 레거시 시스템을 5개 업무 플랫폼으로 통합
- 프론트엔드, 백엔드, 데이터 이전, 외부 연동, 배포 환경 담당
- 최근 AI 에이전트와 Local LLM을 개발 과정과 업무 자동화에 적용

`KWE Transformation Journey`는 `KWE 주요 업무`로 바꾼다. 2022년부터 현재까지의 업무를 연도, 업무, 내용으로 나눈 평범한 표 형태로 표시한다. 현재의 네 단계는 유지하되 `고속`, `전환 여정` 같은 수식은 제거한다.

대표 수치는 카드 대신 `주요 결과` 표에 넣는다.

- 15종 이상 레거시 시스템을 5개 업무 플랫폼으로 통합
- 건당 10분이 걸리던 조회를 5초 이내로 단축
- 삼성 NERP 입력 RPA로 월 1,200시간 상당 반복 작업 절감
- Oracle 데이터 1,000만 건을 PostgreSQL로 이전하고 정합성 검증

### 2페이지: 주요 프로젝트

페이지 제목은 `주요 프로젝트`로 한다. 서론 문장과 영문 제목은 넣지 않는다.

각 프로젝트는 `기간 / 사용 기술 / 배경 / 담당 업무 / 결과` 순서로 작성한다. 세 프로젝트의 문장 구조를 억지로 동일하게 맞추지는 않되 필요한 정보를 찾는 위치는 통일한다.

1. KWE 업무 플랫폼 통합
2. AI를 활용한 MVP 개발과 업무 검증
3. Local LLM 기반 문서 처리와 담당 업무 검색

AEPOS, 삼성 전세기, OneDrive 자동화는 두 번째 프로젝트의 구체 사례로만 사용한다. AEPOS를 이력서 전체를 대표하는 이름으로 쓰지 않는다.

`AI 에이전트 기반 MVP와 업무 발견`은 `AI를 활용한 MVP 개발과 업무 검증`으로 바꾼다. `MVP가 결과물인 동시에 요구사항을 찾는 도구` 같은 결론형 문장 대신 실제로 무엇을 만들었고 어떤 예외를 발견했는지 적는다.

### 3페이지: 경력과 기술

페이지 제목은 `경력 및 기술`로 한다.

- `경력`: KWE Korea, ILJIN Global의 회사명, 직급, 기간, 주요 업무
- `기술`: 백엔드, 프론트엔드, 데이터베이스, 운영, AI·자동화
- `개인 프로젝트`: 댓글 필터의 구현 내용과 링크
- `기술 전환 경험`: VB6, C#/.NET, Node.js/NestJS 순서의 주력 스택 전환

`여러 기술을 거쳤지만, 문제를 푸는 기준은 같았습니다`, `새로운 코드베이스에 들어가는 방식` 같은 자기 해석형 제목은 제거한다. JVM 운영 경험이 없다는 사실은 Java/Kotlin을 기술 목록에 넣지 않는 방식으로 정직하게 표현한다. 기술 전환 경험에는 실제로 사용한 스택과 공통 백엔드 설계 경험만 적는다.

## 문체

- 회사명, 기간, 수치, 시스템명, 기술명을 임의로 바꾸지 않는다.
- `~해 왔습니다`를 반복하지 않고 완료한 일은 과거형으로 쓴다.
- `큰 그림`, `혁신`, `고속`, `여정`, `맞닿다`, `발견의 도구` 같은 홍보성·해석형 표현을 사용하지 않는다.
- AI 도구 이름을 나열하기보다 AI를 사용한 단계와 직접 확인한 결과를 적는다.
- 프로젝트마다 모든 문장을 같은 길이와 종결형으로 맞추지 않는다.
- 이력서에 없는 의미를 윤문 과정에서 추가하지 않는다.

## 검증 기준

- 모든 푸터가 `limgiho`로 표시된다.
- 영문 eyebrow, 장식용 번호, 카드형 성과 지표가 없다.
- 섹션 제목만 읽어도 일반적인 경력 이력서 구조로 보인다.

- Java 또는 Kotlin 실무 경험을 암시하지 않는다.
- 기존에 확인된 수치와 고유명사가 유지된다.
- A4 3페이지이며 본문이 잘리거나 푸터와 겹치지 않는다.
- PDF를 이미지로 렌더링해 세 페이지를 직접 확인한다.
