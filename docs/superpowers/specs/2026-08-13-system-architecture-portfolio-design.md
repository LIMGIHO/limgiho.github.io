# 시스템 아키텍처 인터랙티브 포트폴리오 — 설계

작성일: 2026-08-13

## 배경과 목적

기존 이력서(Jekyll 사이트 + PDF)는 "무엇을 했다"의 나열이라 변별력이 없었다. 회사에서
진행한 물류 포워딩 플랫폼(모노레포: Next.js + NestJS + Worker)의 **시스템 전체 흐름도**를
메인에 두고, 노드·엣지를 클릭하면 **설계 판단의 근거**가 나오는 단일 HTML 포트폴리오를
만든다.

핵심 주장 세 가지:

1. 파편화된 13종 레거시(VB6, C# WinForms, C# 자동화)를 하나의 플랫폼으로 통합했다
2. 백엔드는 클린 아키텍처, 프론트는 FSD — 서로 다른 문제에 서로 다른 경계를 적용했다
3. 서류 판독에 온프레미스 LLM을 도입하고, 그 신뢰도를 측정으로 확인했다

## 제약

- **완전 익명화.** 회사명·제품명·거래처명·사내 IP를 모두 치환한다.
- **단일 HTML 파일.** 외부 의존성 없음. 어디든 올리고 첨부할 수 있어야 한다.
- **정보량 통제.** 카드는 10장, 각 4줄. 더 쓸 말이 있어도 쓰지 않는다.

### 익명화 매핑

| 원본 | 치환 |
|---|---|
| KREAM Web / kwe | LogiFlow (가칭) |
| 삼성 (samsung) | 제조사 A |
| 애플 (apple) | 제조사 B |
| `10.33.34.59:1234` | `llm.internal:1234` |
| UFS / LIMO | 글로벌 포워딩 시스템 / 사내 물류 시스템 |
| 화면 코드(aire2006 등) | 노출하지 않음 |

UNI-PASS(관세청 공개 API), Descartes(상용 EDI 플랫폼), TMS(일반 용어)는 기밀이 아니므로
실명을 유지한다. 실제 디렉터리 트리는 노출하지 않고, 계층 구조만 일반화해 표현한다.

## 화면 구조

단일 페이지. 스크롤 없이 한 화면에 흐름도가 들어가고, 클릭 시 우측 패널이 열린다.

### 1. Before / After 좌우 비대칭 배치 (최상단)

이 포트폴리오의 첫 3초를 담당한다. **토글이 아니라 둘을 나란히 놓는다** — 토글은 누르지
않은 사람에게 가장 강한 부분을 영영 보여주지 못한다.

좌측 35%가 BEFORE, 우측 65%가 AFTER. 반반이 아닌 이유는 BEFORE의 라벨이 읽힐 필요가
없기 때문이다. "엉켜 있다"가 메시지 전부라서 작고 빽빽할수록 대비가 세진다.

**BEFORE** (좌, 비대화형) — 13종 클라이언트가 DB·외부 시스템에 각자 직접 연결된 N×M 그물.
문제 라벨을 아래에 세로로 쌓는다: 동일 로직 중복 구현 / 장애 원인 추적 불가 /
신규 연동 시 13곳 수정.

**AFTER** (우, 대화형) — 계층으로 정리된 현재 구조. 클릭 대상은 여기에만 있다.

```
                    [Web · Next.js]
                          │ REST
                    [API · NestJS]  ←─ [Legacy Express] 전환 중
                     │           │
        ┌────────────┘           └── enqueue ──▶ [Redis · BullMQ]
        │                                              │
   [external 어댑터 층]                             [Worker]
   UNI-PASS · Descartes · 글로벌 포워딩             cron + 분산락
   · TMS · 제조사 EDI · 계근대 · FTP/LDAP               │
        │                                          [Batch]
   [Oracle · MySQL · PG · ODBC]              [Local LLM] ←OCR fallback

   ────── GitLab CI → Kaniko → Docker Swarm (dev/stg/prod) ──────
```

### 2. 클릭 → 하단 패널

패널은 두 다이어그램 아래에 전체 폭으로 놓인다. 3단 고정:

1. **역할** — 한 문장
2. **구조** — 내부 계층 (익명화된 일반화 트리)
3. **설계 결정 카드** — `문제 → 대안 → 선택과 근거 → 결과` 4줄

노드뿐 아니라 **엣지(화살표)도 클릭 대상**이다. API→Redis→Worker 화살표의 정체가 곧
`batch-contract`이므로, 그 이야기는 노드가 아니라 선에 붙는 것이 맞다.

**초기 상태에 "왜 통합인가" 카드를 띄운다.** BEFORE가 클릭 대상이 아니므로 그 카드는
패널의 기본값이 된다. 클릭하지 않아도 핵심 주장이 읽히고, 빈 안내문 화면이 사라진다.

## 카드 10장

| # | 클릭 지점 | 카드 요지 |
|---|---|---|
| 1 | 패널 초기 상태 | **왜 통합인가** — N×M 직접 연결 → 어댑터 한 층으로 수렴. 신규 연동 수정 지점 13곳 → 1곳 |
| 2 | **Web 노드** ★ | **클린 아키텍처를 프론트에 넣으려다 접었다** — 백엔드에서 효과 본 레이어 분리를 이식하니 계속 억지스러웠다. 화면이 곧 업무 단위인 업무 화면 90여 개에서는 레이어가 아니라 슬라이스가 맞았다. 도메인 `features/` + 화면 로컬 `_features/`(container·view) FSD로 정착 |
| 3 | API 노드 | **경계를 타입으로 강제한 클린 아키텍처** — `core/system/external/port` 4분할, 도메인은 Symbol 포트만 안다. 문서유형 추가 시 핸들러 미연결이면 컴파일 실패 |
| 4 | Legacy API | **한 번에 갈아엎지 않았다** — Express를 살려둔 채 모듈 단위로 NestJS 이전, 공용 라이브러리도 구·신 병행 |
| 5 | API→Redis→Worker 엣지 | **잡 계약 패키지** — 배포 단위가 다른 프로듀서·워커가 큐 이름·잡 타입·페이로드를 한 패키지에서 공유. 계약 위반이 런타임이 아니라 빌드에서 터진다 |
| 6 | Worker 노드 | **replica 2개에서 크론이 두 번 도는 문제** — node-cron + Redis 분산 락 |
| 7 | Local LLM 노드 | **서류를 밖으로 내보낼 수 없다** — 사내 온프레미스 추론 서버(OpenAI 호환). JSON Schema로 출력 강제 + 신고번호 정규식 교차검증, PDF 텍스트 품질 판정 후 OCR fallback |
| 8 | Local LLM (2장째) | **믿지 않고 측정했다** — 같은 문서를 반복 추출해 결과를 DB에 적재하는 평가 하네스. OCR이 부모 프로세스 메모리를 반환하지 않아 자식 프로세스로 격리 |
| 9 | external 어댑터 층 | **외부 8종을 한 경계 뒤로** — 외부 장애가 도메인으로 새지 않는다 |
| 10 | CI/CD 띠 | **모노레포에서 바뀐 것만 배포** — `rules:changes`로 변경 앱만 파이프라인 실행, 브랜치=환경, build가 push한 커밋 SHA 태그를 deploy가 그대로 사용 |

2번이 대표 카드다. 나머지 9장은 "잘 만들었다"의 증거지만, 2번만이 "생각할 줄 안다"의
증거다. Web 노드에 시각적 강조(배지 또는 테두리)를 준다.

**의도적으로 뺀 것**: DB 계층 카드, Batch 노드 카드, ag-grid, Kaniko 상세, 큐 분리 상세,
어댑터 개별 7장. 그림에는 남으므로 규모의 인상은 유지되고 읽을 분량만 줄어든다.

## 구현 방식

단일 HTML. 세 덩어리로 나눈다.

- **데이터** — 노드·엣지·카드를 하나의 JS 객체 리터럴로 선언. 다이어그램과 패널은 모두
  이 객체에서 렌더된다. 내용 수정 시 이 객체만 고치면 된다.
- **다이어그램** — 인라인 SVG 두 개. BEFORE는 좁은 세로형 viewBox, AFTER는 넓은 viewBox를
  각자 갖는다. 라이브러리 없음.
- **패널** — 두 다이어그램 아래 전체 폭. 카드는 4줄 고정 포맷이고, 폭이 넓으면 2단으로
  흐른다.

라이트/다크 모두 대응한다. 900px 이하에서는 두 다이어그램이 세로로 쌓이고, AFTER만
가로 스크롤 컨테이너를 갖는다.

**성공 기준 하나가 여기서 바뀐다** — "토글 하나로 이해한다"가 아니라 **"스크롤도 클릭도
없이 첫 화면에서 이해한다"**가 된다.
