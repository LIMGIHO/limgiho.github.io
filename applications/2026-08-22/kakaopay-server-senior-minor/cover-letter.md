# 지원 동기 초안

카카오페이 서버 개발자 - 시니어/미성년 사용자 전용 서비스에 지원합니다. 시니어 사용자의 간편한 홈과 미성년 사용자의 학교생활·알림처럼 사용자의 일상에 직접 닿는 기능은 빠르게 만드는 것만큼 오래 안정적으로 운영하는 일이 중요하다고 생각합니다. 저는 기능 하나를 추가하는 데서 멈추지 않고, 그 기능이 어떤 데이터와 외부 시스템을 거쳐 실행되며 실패했을 때 어떻게 다시 확인되는지까지 설계해 왔습니다.

2010년부터 제조·물류 현장의 업무 시스템을 개발했습니다. KWE에서는 15종으로 흩어져 있던 운영 시스템을 하나의 플랫폼으로 통합하면서 Web·API·Queue·Worker·Data 경계를 나눴습니다. API에는 도메인 로직을 모으고, 오래 걸리거나 실패할 수 있는 작업은 Redis·BullMQ 큐와 Worker로 분리했습니다. Worker는 DB를 직접 다루지 않고 API의 같은 유스케이스를 호출하게 해 실행 경로가 두 곳으로 갈라지지 않게 했습니다.

데이터와 운영 안정성도 함께 맡았습니다. Oracle·MySQL·ODBC로 흩어져 있던 운영 데이터를 스키마부터 다시 설계해 PostgreSQL로 통합했고 1,000만 건 이상을 원본과 대상 양쪽에서 교차 검증했습니다. 운영 API가 반복해서 종료된 장애에서는 로그, 설치된 버전, 조회 행수, 반복 측정을 직접 확인해 원인을 좁혔습니다. 문서 처리에서는 사내망 LLM과 OCR을 사용하되 JSON Schema와 정규식으로 결과를 검증하고 실패 사유를 남겼습니다. 배포는 변경 경로를 판별하고 테스트를 통과한 앱만 Kaniko와 Swarm 롤링 업데이트로 배포하는 흐름으로 운영했습니다.

이 과정에서 다섯 부서의 반복 업무를 직접 관찰하고, 화면이 주고받는 요청과 응답을 분석해 자동화 계약으로 바꾸기도 했습니다. 사용자와 운영자의 실제 절차를 듣고 시스템 경계와 예외 규칙으로 정리하는 방식은 시니어·미성년 사용자 서비스의 새로운 기능을 만들고 기존 성능을 개선하는 데에도 이어질 수 있다고 생각합니다. 댓글 필터, 액션독, HealthDog처럼 모바일·웹 제품을 직접 출시하고 운영한 경험도 사용자 관점에서 문제를 확인하는 데 도움이 됩니다.

현재 공개한 자료에서는 Kotlin·Spring을 직접 사용한 근거를 확인하지 못했습니다. 이 부분을 과장하는 대신, NestJS·TypeScript에서 서버 경계와 유스케이스를 설계하고 데이터·비동기·배포·장애를 운영한 실제 경험을 바탕으로 설명하겠습니다. 새로운 언어와 프레임워크를 업무의 경계와 테스트 방식에 맞춰 빠르게 익혀 적용해 온 과정도 면접에서 구체적으로 말씀드리겠습니다.
